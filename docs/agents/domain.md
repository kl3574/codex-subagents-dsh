# Domain docs

This repository has one domain context. Read the root `GLOSSARY.md` and relevant
decisions in `docs/adr/` before exploring an affected area. If they do not exist,
continue; create them only when a term or a consequential decision is settled.

Use glossary terms consistently in specs, issues, tests, and reviews. Keep the
glossary limited to domain definitions, without file paths or implementation
plans. Raise conflicts with an existing decision before changing its behavior.

Record an ADR only for a hard-to-reverse choice with a meaningful trade-off that
a future maintainer would not otherwise understand.
